# Changelog

Per-feature history for Cargonaut, most recent first. Each entry maps to a
merged feature branch (`NNN-name`) and PR. Forward-looking work lives in
[`ROADMAP.md`](./ROADMAP.md); engineering retrospectives live in

- **Feature 043 — File attribute operations: chmod/chown + symlink/hardlink (Feature 031 follow-up, issue #46)** (2026-06-17). Added the reference orthodox-FM file-attribute operations over the local filesystem, on the tagged/focused selection (never the `..` row). **chmod** (`C-x c`) accepts octal (`644`/`0755`) or symbolic (`u+x`, `go-w`, `a=r`) input; **chown** (`C-x o`) changes user/group by name or numeric id (with a confirmation, FR-007); **symlink** (`C-x s`) and **hard link** (`C-x l`) create links to the focused entry. All four are also in the File menu. `cargonaut-vfs` gains four `VfsBackend` methods (`chmod`/`chown`/`symlink`/`hard_link`) with default `Unsupported` bodies (FR-006) implemented in `LocalFs` via `std::os::unix::fs`; a pure `ModeSpec` (octal/symbolic, parse-once-apply-per-file — the SC-004 gate) and a `parse_owner` helper (user/group names resolved via the already-in-tree **`nix`** crate — safe, no `unsafe`). `cargonaut-core` adds `AppError::BadAttr` + `chmod_selection`/`chown_selection`/`create_symlink`/`create_hard_link` (mirroring `App::mkdir`, reusing `selection_or_focused`; per-file failures reported without rollback, FR-010); chown routes through the existing `ConfirmDialog` → core `Command::Chown(String)`. The UI prefills each dialog (chmod=current octal, chown=current `uid:gid`, links=target name) via a new `TextInputDialog::with_initial`. Also fixed a latent menu-dropdown overflow panic (clamped to the buffer) exposed by the 10-item File menu. Recursion (subtree apply) deferred to #65. +34 unit tests (16 vfs incl. mode/owner/op/Unsupported gates, 14 core, 4 ui-tui); workspace green (325 unit + 9 integration); `nix` promoted to a direct dep (already transitive); 2.61 MiB binary, within the 8 MiB ceiling.

- **Feature 042 — Directory hotlist / bookmarks (Feature 031 follow-up, issue #42)** (2026-06-15). Delivered the deferred directory hotlist. `Ctrl-b` (the pre-reserved `Command::BookmarksMenu`, now wired) opens a modal popup listing named bookmarks organized by group; Enter jumps the active pane to the selected bookmark, `[a]` adds the active pane's current directory (prompting `group/name`), `[d]` removes the highlighted entry, Esc closes. Persistence + the `Bookmark`/`Hotlist` types live in `cargonaut-config` (TOML via `default_hotlist_path()` → `~/.local/state/cargonaut/hotlist.toml`, honoring `$XDG_STATE_HOME` — state, not config; `Hotlist::load` never errors so a missing/malformed file degrades to empty, FR-007/FR-013). `cargonaut-core`'s `App` holds the loaded hotlist + `hotlist_path` and exposes `bookmarks()`/`add_bookmark`/`remove_bookmark`/`jump_to_bookmark`; the last reuses `App::quick_cd`, so a missing target surfaces a status with panes + bookmark unchanged (FR-008/SC-004) and dir-history recording comes for free. The popup is a new shared `dialog.rs` widget (`HotlistDialog`, modeled on `TasksPanelDialog`) whose `HotlistRow { display, index: Option<usize> }` carries a non-selectable header per group so grouped display (`Hotlist::grouped()`, SC-007) reuses one selection model; the add flow chains the existing `TextInputDialog` and `parse_bookmark_input` splits `group/name`. Persistence + grouping gated by pure config-crate tests with tempfile paths (race-free, SC-002/SC-005). +22 unit tests (6 config, 8 core, 8 ui-tui); workspace green (276 unit + 9 integration); no new dependencies; binary within the 8 MiB ceiling.

- **Feature 041 — In-session mouse-capture toggle (FR-013 follow-up, issue #38)** (2026-06-15). Delivered the deferred runtime mouse toggle from Feature 031. A new global `M-m` binding (`design/contracts/keymap.toml` → `Command::ToggleMouseCapture`) flips mouse capture without restarting: suspending releases the mouse to the terminal (so Shift+drag native text selection works), resuming re-captures it. The decision is a pure `plan_mouse_toggle(supported, currently) -> MouseToggleOutcome` (Disabled/EnabledNow/SuspendedNow) — unit-tested as a truth table — with the `dispatch_ui_command` arm doing only the thin best-effort `execute!(Enable/DisableMouseCapture)` (best-effort so a non-supporting terminal can't crash the loop, FR-011). State is surfaced two ways (clarified): a transient status-line message per toggle **and** a persistent `[mouse:on]`/`[mouse:susp]`/`[mouse:off]` indicator in the menu-bar's right gutter (no new layout row). A session disabled via `--no-mouse` / `ui.mouse=false` reports "disabled for this session" and never captures (FR-006). FR-007 (preserve state across F3/F4 external programs) needed no new code — `run_external` already reads the live `ui.mouse_enabled` — and exit teardown unconditionally releases capture (FR-008/SC-005), now pinned by a testable `restore_terminal_modes` helper. Help overlay documents `M-m` + the Shift bypass. Reuses the single existing `UiState.mouse_enabled` flag (no second state field) with `config.ui.mouse` as the read-only session-support signal. +10 unit tests; workspace green (254 unit + 9 integration); no new dependencies; binary within the 8 MiB ceiling.

- **Feature 040 — Panel `..` parent entry as first row (FR-020, issue #37)** (2026-06-15). Every non-root pane now shows a synthetic `..` row as its first row; activating it (Enter when focused, or double-click) ascends to the parent via the existing ascent path. At a filesystem root no `..` row is shown and ascent above root stays impossible. The `..` row is not a real entry: it can't be tagged, is excluded from invert/select-by-pattern (even a `..`-matching glob) and from copy/move/delete, and is present regardless of the hidden-file toggle or active name filter. Implemented as a **core-owned virtual-row cursor model**: `PaneState.cursor` now indexes `[.. (when the cwd has a parent)] ++ visible entries`, with new helpers `has_parent`/`parent_offset`/`row_count`/`on_parent_row`/`focused_row` (+ `FocusedRow`); `focused_entry_index()` returns `None` on the `..` row (so the existing selection/copy guards no-op for free), cursor clamps move to `row_count()`, every cursor-reset site defaults to the first real entry (FR-014, clarified), and `Descend` ascends when on the parent row. `PaneView` prepends one themed `..` `ListItem` and copies the virtual cursor verbatim; mouse double-click needed no new logic (it already routes through `Descend`). No keymap change, no new dependencies. +15 tests (10 core, 5 ui-tui; existing pane tests pinned to a root cwd, three mouse/chrome tests updated for the row offset); workspace green (259 unit + 9 integration); binary within the 8 MiB ceiling.

- **Feature 039 — Tasks/jobs panel popup (FR-016/NFR-004, issue #32)** (2026-06-15). Replaced the F12 / `:jobs` status-bar placeholder with a real modal **tasks panel** over the App transfer registry. F12 opens `ActiveDialog::TasksPanel`, a shared `dialog.rs` list widget (`TasksPanelDialog`, modeled on `ResumePromptDialog`) listing every session transfer as `source → destination` + live state/progress; ↑/↓ or `j`/`k` move, Esc/F12 close (zero side effects on panes, SC-005). Per-row actions: `c` cancel (existing token path), `p` pause, `r` resume. **Pause** signals the transfer's cancellation token — which stops the copy loop while leaving its checkpoint sidecar — and records the id in a new `App.paused` set so it renders `Paused` (distinct from `Cancelled`) and is resume-eligible; every other transfer keeps running. **Resume** locates the sidecar via `scan_resumable` on the destination dir and re-arms through the existing `resume_transfer` (same `TransferId`, fresh token), falling back to a from-scratch `submit_transfer` if no checkpoint exists yet. Core adds UI-agnostic `JobView`/`JobStatus` projections + `job_views()` and `cancel_transfer`/`pause_transfer`/`resume_paused(id)` (mirroring the `ProgressView`/`ResumeOfferView` seam; `ShowTasksPanel` dispatch is now a no-op, `CancelCurrentTransfer` delegates to `cancel_transfer`). The widget holds zero core types — the event loop maps row index → id via a fresh `job_views()` snapshot, refreshed every frame (FR-008). No transfer-crate changes. +20 unit tests (10 core incl. the SC-003 three-job pause/resume integration test on a multi-thread runtime; 10 ui-tui widget + wiring); workspace green (244 unit + 9 integration); `TransferId`/`TransferMode` re-exported from `cargonaut-core`; binary within the 8 MiB ceiling.

- **Feature 033 — Panel filter prompt dialog (FR-013, issue #33)** (2026-06-15). Replaced the clear-only `TogglePanelFilter` (Alt-!) with a prompt-driven filter for the focused pane. Alt-! now opens a modal (prefilled with the active filter pattern) reusing the shared, caller-driven `PathInputDialog` from Feature 038; on Enter the pattern is compiled with **`globset`** (case-insensitive; a pattern with no glob metacharacters `* ? [ ] { }` is matched as a `*word*` substring, otherwise as a glob) and applied to the focused pane with the cursor reset to top; an empty/whitespace submit clears the filter (restoring the full listing); an uncompilable pattern keeps the prompt open with an inline error and leaves pane state untouched; Esc reverts. The filter representation moved from a substring `Option<String>` to a compiled `Option<PaneFilter>` (`{ pattern, matcher }`) across `cargonaut-core` (`PaneState`) and `cargonaut-ui-tui` (`PaneView`); `App::set_filter` (synchronous) carries the set/clear/invalid logic and the TUI intercepts the command to open the dialog (core dispatch is now a no-op). Filter persists across directory navigation until cleared. NB: the deferral's "globset plumbing present" claim was inaccurate — only a substring placeholder existed. +16 tests (5 `PaneFilter` compile-rule + 8 `set_filter` core + 1 lib-level injected-input E2E through `handle_key` + 2 repurposed); workspace green (224 unit + 9 integration); `globset` added (its heavy transitive deps were already in the lockfile) — 2.04 MiB binary, within the 8 MiB ceiling.

- **Feature 038 — Quick-cd popup with tab-completion (FR-012, issue #31)** (2026-06-15). Replaced the Alt-c status-bar placeholder with a working inline quick-cd prompt. Pressing Alt-c opens a modal prefilled with the active pane's current directory; Tab completes the final path segment against the pane's VFS directories merged with its recent-directory history (T1.24), recent-visited first and directories only; Enter navigates the active pane through the existing `navigate_to` path (so dir-history recording and invalid-path rejection come for free); Esc cancels with zero side effects; an invalid path keeps the prompt open with an inline error. Logic lives in `cargonaut-core` (`App::quick_cd` + `App::complete_cd` + a relative/absolute/URI path resolver), tested directly as the SC-006 injected-input gate. The UI side adds a **shared, caller-driven `PathInputDialog`** widget (`cargonaut-ui-tui::dialog`) — completions and errors are injected by the event loop so the widget stays sync and backend-agnostic — which **unblocks #32 (tasks panel) and #33 (filter prompt)**. +22 unit tests (16 core, 6 widget); workspace green (212 unit + 9 integration); keymap unchanged (`M-c` was already bound). No new dependencies; binary within the 8 MiB ceiling.

- **Feature 037 — Resume-from-interrupted-transfer: binary wiring + SC-002 gate** (2026-06-15). Connected the already-built resume engine to the running binary and closed the binary-level SC-002 gate (issue #29). The transfer engine (`scan_resumable`/`resume_transfer`/checkpoint sidecars) and the `ResumePromptDialog` widget existed and were unit-tested, but nothing wired them together: `scan_resumable` was never called on launch, `ActiveDialog::Resume` was never constructed, and the `[r]` handler was a no-op stub. This feature adds a resume seam in `cargonaut-core` (`ResumeOfferView` projection + `scan_resume_offers`/`resume_offer`/`start_over_offer`/`skip_offer`, mirroring the `ProgressView` seam so the UI never depends on transfer types); shows the prompt on launch scanning both pane dirs; and routes `[r]`/`[s]`/`[c]` back into the App, rebuilding the prompt from remaining offers after each choice. The SC-002 gate is a PTY integration test (`crates/cargonaut-bin/tests/resume_sigkill.rs`) that drives the real binary through F5-copy → SIGKILL-mid-transfer → relaunch → `[r]` resume → completion → sha256 match, gated behind `CARGONAUT_PTY_TESTS=1` and enabled in CI. A test-only opt-in throttle (`CARGONAUT_TRANSFER_THROTTLE_MIBPS`, no-op when unset) makes the mid-flight kill deterministic. +9 core/throttle unit tests + the gated PTY test; workspace green (191 unit + 9 integration); 2.03 MiB binary.
