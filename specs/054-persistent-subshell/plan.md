# Implementation Plan: Persistent Subshell (Ctrl-o)

**Branch**: `054-persistent-subshell` | **Date**: 2026-06-19 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/054-persistent-subshell/spec.md`

---

## Summary

Add a PTY-backed persistent subshell panel to the TUI, toggled by `Ctrl-o` via a three-state cycle (Hidden → VisibleFmFocus → VisibleShellFocus → Hidden). The subshell panel occupies the lower portion of the screen (configurable; default 33% of content rows). A full ANSI/VT100 terminal emulator (`vt100` crate + `tui-term` rendering widget) renders the shell output within the panel, making cursor-addressing programs (`vim`, `top`, `less`) work correctly. The shell's cwd is kept in sync with the active file-manager panel's directory on every navigation, focus-swap, and tab-switch event. The shell process is spawned lazily on first `Ctrl-o` and kept alive across hide/show cycles.

## Complexity Tracking

No constitution violations requiring justification. The two new workspace dependencies (`vt100`, `tui-term`) are necessary because:
- Full ANSI/VT100 emulation (FR-005, SC-005) requires a parser that handles cursor positioning, SGR colors, and alternate-screen state — this is ~3000 lines of tested Rust to write from scratch.
- The simpler alternative (raw-line display) was explicitly rejected in spec clarification Q2 because SC-005 requires `top`/`vim`/`less` to work correctly.
- `portable-pty` is already in the workspace; only adding it to `cargonaut-ui-tui`'s dep list.

## Risk Register

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| `tui-term` 0.3 API incompatible with ratatui 0.27 | Low | High | Verify in T054.01 compile; fall back to manual cell rendering if needed |
| PTY reader thread leaks on respawn | Medium | Medium | Drop old `SubshellState` (Rust RAII); verify with test |
| cwd-sync race: `cd` arrives after next command | Low | Low | Fire-and-forget is acceptable; panel is authoritative |
| RSS regression with shell + parser heap | Low | Medium | Monitor via `rss_headroom` bench in T054.24 |
| Keypress latency regression (PTY polling in select) | Low | High | PTY poll is non-blocking `try_recv`; no blocking on hot path |
