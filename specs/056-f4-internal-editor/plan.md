# Implementation Plan: Internal F4 Editor

**Branch**: `056-f4-internal-editor` | **Date**: 2026-06-19 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/056-f4-internal-editor/spec.md`

## Summary

Replace the F4 `$EDITOR` shell-out with a built-in full-screen TUI text editor. When the user presses F4 on a plain-text file ≤10 MiB, Cargonaut opens a `FileEditorDialog` (new widget in `dialog.rs`) in `Mode::Editor`. The dialog owns a `Vec<String>` line buffer, handles character insertion/deletion/navigation directly, and saves via `std::fs::write`. The unsaved-changes guard reuses a new three-choice modal (`UnsavedChangesDialog`). Binary files and large files are declined with status messages. The existing `queue_external` / `ExternalTool` infrastructure for F4 is deleted.

**Scale/Scope**: Single file at a time; ≤10 MiB; UTF-8 text only.

#### Changes in `lib.rs`

1. Add `ActiveDialog::FileEditor { widget: dialog::FileEditorDialog }` variant to `ActiveDialog` enum.
2. Add `open_file_editor()` async fn (mirrors `open_file_viewer()`):
   - Resolve symlink
   - Read sample (up to `BINARY_DETECT_BYTES`)
   - Check UTF-8 → decline Binary
   - Check size > `STREAMING_THRESHOLD_BYTES` → decline TooLarge
   - Read full file, detect line ending, construct `FileEditorDialog`
3. Replace `Command::Edit` arm: remove `queue_external` call; call `open_file_editor()` instead; on success set `ActiveDialog::FileEditor` and `Mode::Editor`.
4. Add `ActiveDialog::FileEditor { widget }` dispatch arm (after the viewer arm):
   - Route to `widget.handle_key(key)`
   - On `FileEditorAction::Close` → `active_dialog = None; mode = Pane; refresh_active_pane()`
   - On `FileEditorAction::SaveAndClose` → `widget.save()`; if Ok → close + refresh; if Err → set status_msg
   - On `FileEditorAction::DiscardAndClose` → close + refresh
   - On `FileEditorAction::Swallow` / `UnsavedPromptShowing` → no-op
5. Add `ActiveDialog::FileEditor { widget }` render arm in `draw_frame()`.
6. Delete `ExternalTool` enum and `queue_external` fn.

## Key Implementation Notes

- **`handle_key` receives the raw `KeyEvent`**: Unlike `FileViewerDialog` (which returns an action from keymap-resolved commands), `FileEditorDialog::handle_key` receives the raw key first, checks if `unsaved_dlg` owns focus, then — for keymap-resolvable commands — the dispatcher in `lib.rs` does the lookup and passes a resolved `FileEditorAction`. The split responsibility is: lib.rs resolves `SaveFile`/`EditorQuit` commands from keymap; the dialog handles raw printable chars and navigation keys directly (same pattern as `TextInputDialog`).

- **Rendering the cursor**: Use `ratatui::style::Modifier::REVERSED` on the cell at `(cursor_col, cursor_line - scroll_offset)` (same technique as `render_vt100_screen` in `subshell.rs`).

- **Line number gutter**: Optional for P1; the status bar shows line:col. If adding a gutter, allocate 4-character left margin and adjust content width.

- **Tab character display**: Replace `\t` with 4 spaces during rendering only; store the literal `\t` in `lines`.
