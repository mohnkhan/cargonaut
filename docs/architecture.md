# Cargonaut Architecture

This file is a thin pointer into the planning tunnel under
[`../design/`](../design/) — the source of truth for every architectural
decision. Read `design/spec.md` first, then `design/plan.md`, then the
crate-level rustdoc generated by `cargo doc --workspace --no-deps`.

## Top-level shape

```
┌──────────────────────────────────────────────────────────────┐
│  cargonaut (bin)  — clap + Config::load + App + ui_tui::run  │
├──────────────────────────────────────────────────────────────┤
│  cargonaut-ui-tui                                            │
│   • keymap (TOML → Command → SeqLookup state machine)        │
│   • PaneView (ratatui List + sync_from)                      │
│   • dialog (ConfirmDialog, ResumePromptDialog)               │
│   • run() — tokio::select! event loop                        │
├──────────────────────────────────────────────────────────────┤
│  cargonaut-core                                              │
```

## Phase 1 task coverage

All Phase 1 tasks track in [`design/tasks.md`](../design/tasks.md).
Per-task implementation notes live in [`Learnings.md`](../Learnings.md)
as `Feature NNN` entries — each entry is keyed to the PR that merged
the task so `git blame` + the Feature entry together explain "why was
this written this way".

## Phase 2+

Each phase will run its own `/speckit-clarify` + `/speckit-plan` +
`/speckit-tasks` pass when picked up. The skeletons in
`design/tasks.md` (Phase 4-6) and `design/plan.md` (Cargo workspace
layout extensions) sketch what's coming without committing the
implementation shape.

## Diagrams

ASCII diagrams (sequence + workspace layout) live in
[`design/architecture/`](../design/architecture/). More will be added as
each phase lands a new subsystem.
